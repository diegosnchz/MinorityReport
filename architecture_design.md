# Architecture Design: Minority Report Crime Prediction System

## 1. GAN Architecture on Graphs
The core of theedictive system is a Generative Adversarial Network (GAN) designed for graph data.

### **Generator (The Crime)**
*   **Role**: Simulates the emergence of criminal patterns by generating synthetic node embeddings that mimic the distribution of "criminal" nodes or by predicting hidden edges (relationships) that signify criminal collaboration.
*   **Model**: **GraphSAGE (Graph Sample and Aggregate)** using `SAGEConv` layers.
*   **Reasoning**: GraphSAGE is inductive, meaning it can generalize to unseen nodes (essential for dynamic, evolving criminal networks). It aggregates feature information from local neighborhoods to generate new embeddings. In this context, it takes random noise $z$ and the existing graph structure to output synthetic embeddings $x_{fake}$ or new edge probabilities.
*   **Objective**: To generate subgraphs or node features that the Discriminator classifies as "safe" or "normal", effectively learning to camouflage criminal activity or discover new patterns of crime that bypass current detection methods.

### **Discriminator (The Police)**
*   **Role**: Analyzes the graph to distinguish between actual criminal patterns (real data samples of known threats) and the synthetic patterns generated by the Generator. It assigns a probability that a subgraph/node represents a real threat.
*   **Model**: **GAT (Graph Attention Networks)** using `GATConv` layers.
*   **Reasoning**: GAT uses attention mechanisms to weigh the importance of different neighbors. This is crucial for forensic analysis, as it can highlight *which* connections (e.g., a specific transaction with a known money launderer) contribute most to the classification of a node as a threat.
*   **Objective**: To correctly classify real criminal patterns as "High Risk" (Real) and generated patterns as "Synthesized/Potential" (Fake), minimizing the error in detection.

### **Loss Function**
We utilize a standard **Minimax Loss** (or Binary Cross Entropy) adapted for the graph domain.

$$ \min_G \max_D V(D, G) = \mathbb{E}_{x \sim p_{data}(x)} [\log D(x)] + \mathbb{E}_{z \sim p_{z}(z)} [\log (1 - D(G(z)))] $$

*   **Discriminator Loss**: Maximizes the probability of assigning the correct label to both training examples (known crimes) and generated samples (simulated crimes).
*   **Generator Loss**: Minimizes $\log(1 - D(G(z)))$, which is equivalent to maximizing the probability that the Discriminator is fooled into thinking the generated crime is "real" (or rather, a plausible scenario that fits the environment).

## 2. Distributed Data Pipeline (Edge to Core)

The system operates on a distributed hierarchy to handle real-time data from surveillance and sensors.

### **Step 1: Data Capture at the Edge**
*   **Nodes**: Smart Cameras, Drones, IoT Sensors, Patrol Units.
*   **Action**: Each node captures local observations (e.g., license plates, facial recognition hashes, movement patterns).
*   **Local Processing**: Preliminary graph construction happens locally. E.g., a drone observes interaction between Person A and Person B, creating a temporary edge $A \leftrightarrow B$ with timestamp features.

### **Step 2: Decentralized Knowledge Sharing (Gossip Protocol)**
*   **Problem**: Centralizing every micro-event is bandwidth-prohibitive and introduces latency.
*   **Solution**: A Gossip Protocol.
*   **Mechanism**:
    1.  Each Edge Node maintains a partial view of the local graph.
    2.  Periodically (e.g., every 100ms), a node selects a random peer.
    3.  They exchange "Graph Diffs" or updated Node Embeddings (compressed vectors representing local state).
    4.  This spreads information exponentially fast across the network (epidemic algorithm) without a central coordinator.
    5.  **Output**: A convergence of the distributed graph state across the edge layer.

### **Step 3: Centralized Inference (GNN Inference)**
*   **Aggregation**: Aggregated graph snapshots are periodically pushed to the central inference servers.
*   **Inference**: The pre-trained GAT (Discriminator) consumes the updated graph topology.
*   **Prediction**: It identifies high-risk nodes or subgraphs (predicted crimes).

### **Step 4: Persistence or Visualization (Neo4j)**
*   **Storage**: The graph structure and prediction results are stored in **Neo4j**.
*   **Neo4j Graph Data Science (GDS)**: utilized for projecting the graph into memory for training updates or complex analytics.
*   **Write-back**: Risk scores and "Pre-Crime" alerts are written back as properties on the User/Location nodes for visualization by analysts.
